# Repo Map

A navigation guide for the GalleryAgentAI repo (the **Mochi** project). The root has grown ~190 `.py` files over many iterations; this map points you to what's actually live so you don't have to read all of it. See `CLAUDE.md` for philosophy and rules.

## Run it

| What | Command |
|---|---|
| Backend API (production) | `python -m uvicorn api:app` (FastAPI, port 8001) |
| Frontend (dev) | `cd frontend && npm run dev` (Vite/React, port 5177) |
| Full pipeline (100+ steps) | `python run_full_mochi_pipeline.py` ⚠️ scrapes web (Tavily, billable) |
| Deploy to Lightsail | `bash deploy.sh` (builds React, rsyncs to the server, verifies 200s) |

## The live system (what to actually read)

- **`api.py`** — the entire FastAPI backend. All `/api/*` endpoints, opportunity bucketing, IBM gating, CRM, Peppercorn/Saffron data. This is the heart of the served app.
- **`frontend/src/`** — the React app (the real UI).
  - `components/` — the three companion pages: `TodaysFocus`/`HeroSection`/`OppCard` (Mochi), `PeppercornPage`, `SaffronPage`, plus `OppDetailPanel`.
  - `i18n/translations.js` — zh/ja/en strings (744 keys each); `data/saffron_insights.js` — Saffron's static market/revenue data.
- **`engines/`** — ~60 pipeline engines (one per reasoning step). Key one: `exclusive_strategy_bucket_engine.py` owns every opportunity's `exclusive_primary_bucket` (see CLAUDE.md → Data Patch Rule).
- **Pipeline drivers (root):** `run_full_mochi_pipeline.py` (active, the 100+ step list) → `smart_pipeline_runner.py` (resolves each step name across root → `engines/` → `ui/` → `scripts/runners` → `scripts/patches`). `council_pipeline_agent.py` is the legacy 11-step pipeline (still functional). `enriched_to_compact_opportunities.py` compacts enriched → served data.
- **`deploy.sh`** — the deploy. Uses an SSH key at `Web/*.pem` (gitignored — never commit keys).

## Data (state lives in JSON, no DB)

- `memory/` — **DATA_DIR** the API reads at request time: `artist_master_profile.json` (source profile + `social_presence`), `peppercorn_profile.json` (app state), `contact_memory.json` (CRM), `submission_log.json` / `exhibition_log.json` (logged events), generated reports.
- `deploy_data/compact_opportunities.json` — the master served opportunity list (pipeline-generated; bucket field is engine-owned).
- `Memory/` (capital M) — pipeline output mirror; on Windows it collapses into `memory/`, on the Linux server it's separate. `deploy.sh` copies the specific files the API needs.
- **Before hand-editing any JSON, read CLAUDE.md → The Data Patch Rule.** `reports/algorithm_vs_patch_audit.md` and `reports/patch_exceptions.md` track which fields are engine-owned vs. patched.

## Legacy / cleanup status

The root accumulated many one-shot scripts and superseded agents/apps from earlier (Streamlit-era) iterations.

- **Archived 2026-06-10:** 29 provably-dead root scripts (zero references anywhere — not imported, not in any pipeline/launcher/doc) moved to `archive/dead_code/legacy_root_2026-06/`.
- **Not yet archived (~135 root scripts):** referenced only in historical docs (`_bible/ANALYSIS_REPORTS/`) or `data/config/project_manifest.json`, not by live code. Likely legacy but not *provably* dead, so left in place pending review. A future pass can verify and archive these in batches.
- The live app does **not** depend on these — it's `api.py` + `frontend/` + `engines/` + the pipeline drivers above.
